# Спецтехника Минск — лендинг аренды спецтехники

Одностраничный сайт на чистом HTML. Публикуется на GitHub Pages, без сервера
и без сборки в привычном смысле: `npm run build` просто раскладывает файлы
в `dist/` и считает CSP-хеши.

**Сайт:** https://11alone11.github.io/Gruzoperevozki_ai/

---

## Структура

```
.
├── index.html              ← весь сайт: разметка + CSS + JS + JSON-LD одним файлом
├── 404.html
├── robots.txt
├── sitemap.xml
├── site.webmanifest
├── images/
│   ├── amkodor-332-{416,640,832}.{avif,webp}  ← погрузчик Амкодор 332
│   ├── amkodor-342-{416,640,832}.{avif,webp}  ← погрузчик Амкодор 342
│   ├── maz-5551-{416,465}.{avif,webp}         ← самосвал МАЗ 5551
│   ├── icon-*.svg                             ← иконки, прогнаны через SVGO
│   ├── logo.svg, favicon.{ico,svg}, apple-touch-icon.png, icon-*.png
│   ├── og-preview.jpg                         ← превью 1200×630 для соцсетей
│   └── source/                                ← исходники (в публикацию не идут)
├── scripts/
│   ├── build.mjs              ← собирает dist/ и вписывает CSP
│   ├── set-domain.sh          ← замена домена одной командой
│   └── lint-inline-script.mjs ← линтинг инлайнового <script>
├── .github/workflows/deploy.yml
├── .prettierrc.json, .editorconfig, eslint.config.js
└── package.json
```

Почему CSS и JS внутри `index.html`: для одностраничника это убирает два
блокирующих рендер запроса. Обе части отформатированы, минификации нет.

**Именование:** BEM (`.machine-card__name`, `.reviews__dot`), файлы картинок —
по содержимому (`maz-5551-465.avif`, а не `card_3.webp`), суффикс — ширина варианта.

## Разработка

```bash
npm install
npm run check      # prettier + eslint, ничего не меняя
npm run build      # собрать dist/
```

Посмотреть локально:

```bash
npm run build && npx serve dist
```

| Команда          | Что делает                                                      |
| ---------------- | --------------------------------------------------------------- |
| `npm run build`  | собирает `dist/`, вписывает CSP-хеши, кладёт `.nojekyll`        |
| `npm run format` | Prettier: HTML (вместе с инлайновыми CSS/JS), CSS, JS, JSON, MD |
| `npm run lint`   | ESLint: скрипты сборки и инлайновый `<script>` из `index.html`  |
| `npm run check`  | форматирование + линт, без изменений на диске                   |

## Деплой на GitHub Pages

Публикация автоматическая: **push в `main` → GitHub Actions → GitHub Pages**.
Файл воркфлоу — [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml).

Первая настройка (делается один раз):

1. Settings → Pages → **Source: GitHub Actions**.
2. Push в `main`. Готово.

Адрес проекта: `https://<ник>.github.io/<репозиторий>/`.

> **Важно:** на бесплатном тарифе GitHub Pages работает только для
> **публичных** репозиториев. Для приватного нужен GitHub Pro либо другой хостинг.

Сборка перед публикацией проверяет, что каждая картинка из `index.html`
действительно лежит в `dist/`, — опечатка в пути уронит деплой, а не сайт.

### Свой домен

1. `bash scripts/set-domain.sh borisov-loading.by` — меняет адрес в canonical,
   OG-тегах, JSON-LD, `robots.txt` и `sitemap.xml`.
2. Settings → Pages → Custom domain — вписать домен и включить **Enforce HTTPS**.

## Безопасность

GitHub Pages не позволяет задавать HTTP-заголовки ответа, поэтому всё, что
можно, сделано на уровне разметки и сборки.

| Мера                                                      | Где                                                                         |
| --------------------------------------------------------- | --------------------------------------------------------------------------- |
| **CSP с SHA-256 хешами** вместо `unsafe-inline`           | вписывается в `<meta>` при сборке (`scripts/build.mjs`)                     |
| Политика по умолчанию запрещает всё: `default-src 'none'` | разрешены только свои картинки, один инлайновый `<style>` и один `<script>` |
| `base-uri 'none'`, `form-action 'none'`                   | запрет подмены базы и отправки форм наружу                                  |
| `referrer-policy: strict-origin-when-cross-origin`        | `<meta name="referrer">`                                                    |
| HTTPS                                                     | GitHub Pages выдаёт сертификат сам; включите **Enforce HTTPS**              |
| Нет сторонних скриптов, шрифтов и трекеров                | ноль внешних зависимостей                                                   |
| Нет секретов в репозитории                                | здесь только статика, токенов нет                                           |
| Внешние ссылки                                            | `rel="noopener noreferrer"`                                                 |

CSP считается заново на каждой сборке, поэтому после правки `index.html`
хеши не устаревают — руками ничего поддерживать не нужно.

Что нельзя включить на GitHub Pages: HSTS, `X-Frame-Options`,
`frame-ancestors` (в `<meta>` не работает). Если понадобится — только через
свой прокси или другой хостинг.

## Форма заявок

Бэкенда нет: на GitHub Pages некуда принимать POST. Блок «Свяжитесь с нами»
содержит прямые ссылки `tel:` и `mailto:` — они работают всегда и не теряют
заявки при недоступности сервера.

Если понадобится форма, вариантов три: внешний обработчик (Formspree,
Getform), Telegram-бот через serverless-функцию или свой сервер.

5. **Аналитика.** Счётчиков нет. Если добавлять — помнить, что CSP запрещает

   компании о самой себе, а за разметку невидимого контента можно получить санкции.
